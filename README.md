# Lyric Motion Renderer

歌詞を配置し、動きを振り付けるブラウザ用のKinetic Typography制作ツールです。v0.19.0-dev。歌詞を映像表現の素材として扱い、動画編集ソフトへ重ねる文字演出素材を作ります。

本格的な動画編集ソフトや字幕規格への高度な準拠を目指すツールではありません。生成結果を確認し、必要な部分を手直しする制作フローを想定しています。

## 使う

公開サイト: https://umetana.github.io/lyric-motion-renderer/

通常のデスクトップChrome／Edgeでの利用を想定しています。HTTPSまたはlocalhostで開いてください。フォルダーをダブルクリックしてfile://で開く方式は対象外です。

ローカル実行（Node.js 22以降）:

```sh
npm run dev
```

http://127.0.0.1:8080/ を開きます。インストールが必要なnpm依存はありません。開発サーバーは静的配信だけを行います。

## 基本操作

1. 文字演出サンプルで動作を確認するか、LRC／SRT／歌詞台本を読み込みます。
2. SceneとElementを選び、文字・時刻・フォント・位置を調整します。本文の半角`|`／全角`｜`でフレーズを分割できます。
3. 音源を選び、再生・停止しながら「現在位置を開始／終了に」で時刻を合わせます。Element選択時の自動シークはON/OFFできます。
4. ＋をドラッグして基準位置とX/Y軌道を動かします。数値入力・9方向配置・行の左／中央／右揃えにも対応しています。
5. 複数Elementにチェックして、一括編集や複数振り付けを使えます。動きだけ置き換える場合は「配置・時刻を保持」をONにしてください。
6. 再生・シークで確認し、Animationのキーを個別調整します。Animation欄は折りたたんでプレビューを広げられます。
7. JSONまたは素材込みZIPで保存し、PNG連番またはMP4を書き出します。

歌詞台本の仕様: [LYRIC_SCRIPT_FORMAT.md](LYRIC_SCRIPT_FORMAT.md)。入力例は [sample.lyricmotion](sample.lyricmotion) と [sample-phrase-timing.lyricmotion](sample-phrase-timing.lyricmotion) です。

## 演出・素材

単体プリセットと、斜めImpact・左右交互・ウェーブ・連鎖退場・積み上げ・集合・中央から展開・最後の一語を強調・流れる歌詞の9種類の複数振り付けがあります。生成結果は通常のElementとキーとして編集・保存できます。自動でレイアウトを完成させる機能ではなく、画面外への配置も許容します。

参照背景はPNG／JPEG／WebPを読み込み、表示だけに使用します。動画やPNGへの書き出しには含まれません。Google Fontsの任意名指定は試験機能です。正式名と対応する太さを指定してください。文字が収録されていない場合はブラウザの代替書体が使われることがあります。

## 保存・復帰

- JSONのみ: 軽量な編集データ。音源と参照画像の実体は含みません。
- 素材込みZIP: 音源・参照画像と表示設定を同梱して復帰できます。本ツールが生成する非圧縮ZIPの再読込に対応します。
- 保存: 初回は保存先を選び、以後は上書き。名前を付けて保存は保存先を選び直し、ダウンロードは毎回出力します。ファイル保存API非対応ブラウザではダウンロード方式になります。
- IndexedDBで直近の作業を自動保存します。次回起動時に「復元／破棄」を選ぶまで自動保存は待機します。音源・画像・再生位置も復帰できます。保存先ファイルの権限は復帰しません。

自動保存は同じブラウザープロファイル・同じオリジン内の機能です。別PC・別ブラウザー・ローカル版とは共有しません。ブラウザーデータの削除等で失われるため、手元のファイル保存と併用してください。読み込んだ歌詞・音源・画像はアプリからサーバーへアップロードしません。Google Fontsを選ぶとGoogleへフォント取得リクエストが発生しますが、歌詞本文はリクエストに含めません。

## 書き出しと制約

- プレビューと同じCanvasレンダラーで、フレーム時刻を明示して生成します。
- PNG連番は透過を保持し、フォルダー保存APIに対応したブラウザが必要です。
- MP4は背景色あり・音声なし。H.264エンコーダーの利用可否はブラウザと端末に依存します。ファイルへ直接保存できない環境では短い区間のみ対応します。
- 半透明や発光を色背景へ合成してからクロマキーで抜くと背景色が残るため、色を保つ合成には透過PNGを使ってください。
- キャンバスは各辺64〜3840px、合計3840×2160画素以下、24／30／60fps、長さは最大600秒。Scene／Elementは各上限1000です。
- 素材込みZIPは合計240MB以下。音源200MB・画像30MB・JSON2MB以下。画像は各辺8192px以下・3200万画素以下です。
- 保存・出力のブラウザ互換性は同一ではありません。OBS用ツールではありません。

## 開発・GitHub Pages

```sh
npm test
```

アプリ本体と共通UI部品・Mediabunnyは同梱済みです。バックエンド・ビルド工程・APIキーは不要です。すべての参照は相対パスなので、GitHub Pagesのリポジトリ配下URLでも動きます。

GitHub PagesはSettings → Pagesで「Deploy from a branch」、`main`／`/(root)`を指定します。`.nojekyll`を含めています。個人の音源・歌詞プロジェクト・画像はリポジトリへ追加せず、ブラウザの読込を利用してください。

## Scene／Element一覧の操作

デスクトップの左側はScene一覧（上段）と選択SceneのElement一覧（下段）を独立してスクロールできます。Scene数が増えてもElement一覧は押し下げられません。件数と選択Scene名を表示し、全選択／解除は常時表示します。「Scene編集・読込」「Element操作・選択設定」を開くと、時刻編集・読込・追加削除・自動シーク設定などが使えます。Scene編集欄を開いている間だけ上段を広げます。Scene変更時はElement一覧を先頭へ、同じSceneの編集では現在のスクロール位置を保持します。
